## Why

The 0.8.x series introduced the two-hook system and changelog automation, but
real-world verification exposed one commit-blocking defect and two correctness
drifts that must be fixed before the next release: hooks generated by
`pezin install-hooks` are unexecutable in venv/pipx installs (they abort every
commit), changelog sections are written in the wrong order (violating the
changelog-management spec's promotion requirement), and `pezin --version`
reports stale metadata in editable installs.

## What Changes

- Pin the generated git hook scripts to the interpreter that ran
  `pezin install-hooks` (`sys.executable`) instead of `#!/usr/bin/env python3`,
  so hooks resolve pezin in pipx/uv/venv deployments.
- Generated hooks degrade gracefully: when pezin cannot be imported they print
  a loud warning and exit `0`, instead of blocking the commit with exit `1`.
- Fix `ChangelogManager.update_changelog()` ordering per Keep-a-Changelog: the
  `## [Unreleased]` section stays directly under the header, new version
  sections are inserted below it, entries accumulated under `[Unreleased]` are
  promoted into the released section, and an empty `[Unreleased]` is
  re-created. The existing file's header text is preserved instead of being
  clobbered by the template.
- `pezin --version` reports `pezin.__version__` first (kept in sync as a
  version file) and falls back to `importlib.metadata`, fixing stale
  `0.8.0 (editable)` output.
- Add `python -m pezin` support via `src/pezin/__main__.py`.

## Capabilities

### New Capabilities
- `hook-installation`: `pezin install-hooks` produces executable hooks for the
  installing interpreter and never lets a missing pezin installation block a
  commit.

### Modified Capabilities
- `changelog-management`: `update_changelog()` now keeps `[Unreleased]` at the
  top, promotes its entries into the new version section, and preserves the
  existing file header. The previous behavior left `[Unreleased]` stranded at
  the bottom and never promoted its entries.

## Impact

- `src/pezin/cli/hooks.py` (`create_hook_script` shebang + import-failure
  exit code).
- `src/pezin/core/changelog.py` (`update_changelog`, header handling).
- `src/pezin/cli/main.py` (`get_pezin_version`).
- `src/pezin/__main__.py` (new).
- Tests: `tests/cli/test_hooks_install.py`, `tests/core/test_changelog.py`,
  `tests/cli/test_cli.py`, plus a slow e2e that commits through the generated
  hook with a PATH that cannot see the installing venv.
- No config format changes; no breaking changes. Released as the next patch
  or minor version (0.9.0) since `python -m pezin` is a small feature.
